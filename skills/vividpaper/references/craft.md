# 画法规则：怎样让人 3 分钟看懂

目标只有一个：读者看完，能用自己的话复述这篇论文**解决什么问题、核心做法是什么、为什么有效、效果多好**。每条规则后面是交付前要问自己的问题。

## 1. 一条主线，一个主角

- 片头的 `question` 是主线；每一幕的标题都要回答它的一部分。顺序一般是：老办法哪里不行 → 核心想法 → 机制拆开 → 关键细节 → 整体结构 → 结果。
- 选一个具体例子当主角，从第一幕跟到最后（Attention 那篇是句子里的 its）。机制讲到哪一步，就让主角走到哪一步。
- 次要的变体、消融、附录里的技巧，一句话带过或不讲。
- 问：删掉任何一幕，主线还讲得通吗？讲得通就删掉它。

## 2. 用论文的真图和真数

- 架构图、关键示意图、注意力可视化这类，用 `crop.py` 裁原图，放在白底卡片上（`card: true`），讲到哪里就用 `g.mark` 框到哪里，旁边写出处（`g.note('图：论文 Figure 1', …)`）。
- 论文原图字太小、太乱时，用论文里的数据**自己重画**，角落写出处。
- 标签会盖住原图里的字时，用 `g.mark` 的 `leader` 把标签拉到图外。
- 论文的成品样张墙（一大片生成结果）不放；要展示效果，挑一两张讲机制用得上的。
- 结果用 `g.bars` 画成条形图，不做文字表格。标题写方向：「BLEU ↑ 越高越好」「算力 ↓ 越少越好」。坐标不从 0 开始要注明。
- 示意用的数字（例如演示 softmax 的分数）要写「示意」。
- 问：画面上每个数字都能在原文里找到吗？示意的数字标了「示意」吗？

## 3. 每句字幕都有一个画面动作

- 字幕负责整句话，画面只放**标签和数字**；不要把字幕内容再写一遍在画面上。
- 每句字幕开始后 0.3–1 秒，画面上要有一个和这句话对应的动作：东西出现、移动、连线、标框、变色。用 `g.p(L(i) + …)` 挂在字幕上。
- 图先整个出现，再逐项标框讲解；不要文字先于图出现。
- 一句话里讲两件事，就分两次动（例如先框 Law，过 1.5 秒再框 application）。
- 不做来回闪烁、随机乱跳的高亮；说到哪个，哪个由暗变亮并保持住。
- 动作要有一定面积：图形出现、移动、标框、连线都算；一行小字淡入在手机上几乎看不出来，自查也可能认不出。
- 入场在画面内完成（淡入、短距离位移），不要从画面外滑进来。
- 问：静音看，光看画面能猜出这句字幕大概在讲什么吗？

## 4. 一屏只有一个主体

- 一幕只讲一个东西；用不到的元素淡出或压暗（alpha 0.3 左右），不要堆满。
- 同一个概念在所有幕里用同一种画法和颜色（Q 一直是赭橙、K 一直是蓝、V 一直是绿）。
- 第一次出现的术语、缩写、符号，在字幕里用一句大白话解释（「d_k = 64，防止分数太大」）。
- 公式只出现一次，放在讲完机制之后，用颜色和前面画过的东西对上号。
- 问：同一个东西在前后几幕里，形状、颜色、位置一致吗？

## 5. 手机上看得清

- 画面字号 ≥ 24px（出处小字 ≥ 20），重要标签 ≥ 30px；字幕引擎固定 42px、最多两行（约 44 个汉字以内）。
- 公式和符号不用组合附加符号（上划线、帽子、波浪号叠在字母上）：ᾱ 写成 ā，ε̂ 写成「ε 的预测值」或 ε_θ。
- 内容放在 y 130–1190，左右留白 ≥ 20。
- 问：check.py 的 sheet 缩小成手机大小，还能看清主体吗？

## 6. 时长

- 一幕 15–25 秒、3–5 句字幕；全片 2.5–3.5 分钟。超过 4 分钟就砍幕，不要加快字幕。
